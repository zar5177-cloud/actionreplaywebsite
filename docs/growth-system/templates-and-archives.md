# Self-Leak And Fake Archive Templates

The self-leak system is not “pretend to leak.” It is: publish the kind of half-damaged working material that would normally stay in a production folder. The asset should look like it survived the process, not like it was designed for the feed.

## Self-Leak Rules

- One specific artifact per post. Do not bundle six unrelated ideas just because the carousel has room.
- Use filenames, folders, timestamps, and mundane defects.
- Let product appear as a clue, not always the subject.
- Keep one human trace: a cursor, flash reflection, red pen, bad crop, finder sidebar, printer dust, text layer name.
- Never fake private customer data, real orders, real addresses, payment info, or real support conversations.
- Use fictional usernames, fictional thread structures, and fictional account IDs.

## Self-Leak Templates

### Blurry Screenshot

Visual: phone photo of a laptop screen. Product is visible only as a thumbnail, partly blocked by glare.

Caption prompt: `found the wrong preview in [folder]. timestamp says [time] but the export was made later.`

Required details:

- filename visible,
- one folder name that sounds internal,
- one UI element cropped off,
- no full product reveal.

Post prompts:

- `EXPORTS/drop2/slotb_preview_03.jpg`
- `old_site_restore/nav_buttons_active.psd`
- `AR002_packaging/_wrong_blue/printproof.png`
- `forum_mirror/images_missing/thread_17_capture.jpg`

### Accidental Export

Visual: clean-ish graphic with export artifacts, crop marks, unused layer visible, wrong aspect ratio.

Caption prompt: `not the approved file. too late now.`

Required details:

- `FINAL` used incorrectly,
- one red mark or layer label,
- slight channel offset,
- product copy too close to an edge.

Post prompts:

- fake magazine ad where `price` layer is hidden,
- poster crop with `do not post` written in the margin,
- tee back print shown on transparent checkerboard,
- barcode sticker exported at wrong resolution.

### Fake Folder Preview

Visual: screenshot of Finder/List view or styled folder grid.

Caption prompt: `opened the old folder again. some files changed order.`

Required details:

- at least eight filenames,
- mixed dates,
- one folder named like an abandoned experiment,
- one file with size `0 KB`.

Example filenames:

- `AR002_SLOTB_BACKPRINT_v4.png`
- `do_not_restore_sponsor_line.txt`
- `issue00_scan_page17.tif`
- `first20_postmortem_notes.rtf`
- `mysterygift_window_old.html`
- `wrong_sticker_keep.ai`
- `customer_photo_REDACTED_fake.png`
- `memorycard_dump_0207.bin`

### Old Forum Repost

Visual: fake forum screenshot or quote crop.

Caption prompt: `mirror recovered without avatars. one attachment still dead.`

Required details:

- fictional usernames,
- reply count,
- timestamp,
- one broken image placeholder,
- no real forum branding.

Thread prompts:

- `did anyone else find the blue pixel?`
- `action replay shirt in old scan?`
- `restock thread locked by mod`
- `slot b save has different item name`

### Corrupted Image Preview

Visual: partial product image with repeated scanlines, broken chunk, or color channel drift.

Caption prompt: `preview opens for 2 seconds then does this.`

Required details:

- keep at least one legible product clue,
- avoid total illegibility,
- add checksum or error label.

Prompts:

- tee graphic broken into four horizontal bands,
- packaging label with half of barcode readable,
- QR code with one corner missing but still scannable in story,
- old ad where the product is the only clean object.

### Fake Rejected Ad

Visual: print ad proof with marked-up reasons for rejection.

Caption prompt: `rejected for sounding like a warning screen.`

Required details:

- one rejection note that is too specific,
- fake issue/page number,
- crop marks,
- no real magazine masthead.

Rejection notes:

- `too much like evidence`
- `shirt reads as unlock item, not apparel`
- `barcode looks like a dead link`
- `do not say limited. show it.`
- `page 17 missing context`

### Fake Production Notes

Visual: notes app screenshot, printed sheet, or handwritten card beside object.

Caption prompt: `note from the table. not a plan.`

Required details:

- one useful instruction,
- one emotionally strange line,
- one hard constraint.

Fragments:

- `do not fix the countdown`
- `box should feel like it arrived late`
- `first run mistake stays archived`
- `blue has to look wrong under flash`
- `make the code smaller, people need to search`

### Packaging Test

Visual: mailer, sticker, tape, folded shirt edge, label sheet.

Caption prompt: `packaging test. sticker version 2 survives better.`

Required details:

- handheld or desk lighting,
- visible scale,
- one flaw called out.

Prompts:

- flash photo of label sheet,
- envelope corner with `AR-002 / SLOT B`,
- sticker half peeled off plastic sleeve,
- hangtag on wrong garment.

### Hidden Product Preview

Visual: product partly obscured by another artifact.

Caption prompt: `the visible part is not the clue.`

Required details:

- one code hidden in image,
- one visible product feature,
- no complete front/back reveal.

Prompts:

- back print reflected in CRT,
- sleeve graphic visible under shipping paper,
- tag close-up with hidden page slug,
- product image cropped to show only shadow and print edge.

## Fake Historical Documentation System

Every fake document needs three labels:

- `artifact type`: what it is supposed to be,
- `fictional source`: where it was recovered from,
- `recovery defect`: what is wrong with it.

### Fake Receipt

Use for: inventory lore, first-run scarcity, not real payment proof.

Do:

- call it `packing ledger`, `stock pull`, or `inventory slip`,
- use fictional SKUs,
- remove addresses and payment fields,
- add printer defects.

Template:

```text
ACTION REPLAY STOCK PULL
terminal: WORLD_OVERRIDE_03
time: 2007-02-27 02:14
item: AR-002 SLOT B GARMENT
qty pulled: 20
qty held: 03
note: do not label as restock
```

### Fake Dev Notes

Use for: making hidden pages feel tested.

Template:

```text
BUILD NOTE 0.8
- code input accepts lowercase after cache clear
- forum mirror too readable
- product preview should not appear before flag
- leave one clickable pixel
- do not explain slot b
```

### Fake GameFAQs Thread

Use for: guide fragments, rumor structures. Do not use real GameFAQs branding.

Template:

```text
CHEAT_ARCHIVE TXT MIRROR
topic: hidden event active???
user: walkthrough_txt
date: 02/27/07 12:19AM

do not brute force it. check the weird UI pieces first.
last time they logged bad entries and half the thread disappeared.
```

### Fake Inventory Sticker

Use for: product shots, packaging, collector value.

Template:

```text
AR-002 / SLOT B
RUN: FIRST RESTORED
PULLED: 20
FLAG: MEMORYCARD
CHECK: BLUE OK / PINK OFF
```

### Fake Old Website Screenshot

Use for: website clues and archive pages.

Required sections:

- bad nav buttons,
- one broken image,
- one status line,
- one tiny code hidden in footer,
- old copyright line that does not resolve cleanly.

Copy fragments:

- `event flag active`
- `shop visible to verified saves`
- `do not refresh during mystery gift`
- `mirror unstable after 00:00`

### Fake Magazine Scan

Use for: artifacts that can be reposted by design/moodboard pages.

Required details:

- fake issue number,
- crop marks,
- paper texture,
- one correction or missing page note,
- no real publication names.

Copy fragments:

- `the garment that loads like a cheat menu`
- `worldwide unlock culture`
- `not all codes are meant to be shared`
- `mail-order form removed from archive`

### Fake Japanese Import Listing

Use for: global collector psychology.

Do:

- use fictional shop names,
- keep translation awkward but respectful,
- avoid fake claims about real Japan-only releases.

Template:

```text
IMPORT LISTING / SHOP UNKNOWN
item: action replay world override shirt
condition: unopened / event paper included
note: color differs from photograph
translation: "street code garment, not game software"
```

### Fake Tournament Flyer

Use for: street/gaming crossover.

Required details:

- venue name invented,
- time and bracket,
- side note about sticker or hidden code,
- print wear.

Copy fragments:

- `no outside memory cards`
- `winner receives promo insert`
- `late signups use slot b`
- `bring your own controller`

### Fake Beta Tester Document

Use for: product quality and hidden page details.

Template:

```text
SLOT B TESTER REPORT
build: 0.7.3
tester id: hidden
result: shirt preview loads before code
severity: acceptable
note: bug feels better than fix
```

### Fake Customer Support Email

Use sparingly. Do not imitate a real platform, processor, or brand. Keep it fictional and artifact-like.

Template:

```text
from: support@worldoverride.local
subject: RE: event flag not clearing

we cannot reset the save from here.
if the item appears twice, keep the older one.
do not reply with codes in the subject line.
```

## Documentary Realism Shot List

Post these between archive pieces so the mythology has physical proof.

- Test print on table, harsh phone flash, visible dust.
- CRT monitor showing hidden event page, product box in reflection.
- Packaging mockup with sticker placed crooked.
- Handwritten note beside a ruler: `code too big`.
- Failed attempt: shirt color wrong under bathroom light.
- Rejected design laid over final design, neither centered.
- Shipping prep with labels redacted, no customer data.
- First drop postmortem: three bullets, one mistake, one unresolved clue.
- Printer calibration bars next to sticker sheet.
- Screenshot of localStorage unlock flags on a development browser.
- Tape test on mailer after being peeled once.
- Stack of blank shirts with only one tag visible.

## Posting Structure For Proof Content

Slide 1: imperfect evidence photo.

Slide 2: close crop of the useful detail.

Slide 3: note, receipt, or production label.

Slide 4: product implication, not full reveal.

Caption: one sentence, one filename, one unresolved phrase.
