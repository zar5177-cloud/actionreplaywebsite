# Drop, Unlock, Outreach, And Metrics System

## Micro-Community Infiltration, Manual Only

This is not infiltration through deception. It is showing up manually in adjacent communities with artifacts worth saving, then making it easy for page owners to repost something that fits their taste. No scraping, no spam lists, no mass DM software.

### Communities

- Gaming nostalgia pages.
- PS2, DS, GameCube, handheld, cheat-device, and magazine archive accounts.
- Old internet aesthetic pages.
- Frutiger Aero and webcore pages.
- Experimental graphic design pages.
- Streetwear micro-pages.
- Collector pages: stickers, posters, physical media, game ephemera.
- Archive and moodboard accounts.

### Search Keywords

Use Instagram, TikTok, Pinterest, Are.na, Reddit, Tumblr, and Google manually.

### Daily Routine

1. Save 10 posts that genuinely fit the world.
2. Leave 8-15 specific comments from the main account or one relevant side account.
3. DM 1-3 accounts only if a post already creates a natural opening.
4. Offer one repostable artifact, not a pitch deck.
5. Log who replied, what they reposted, and whether their audience saved or commented.

### Comment Strategy

Good:

- `the crop marks make this feel like evidence`
- `this belongs next to old cheat-device ads`
- `i forgot how serious handheld promo pages felt`
- `the scan texture is the whole thing`

Bad:

- `check us out`
- `collab?`
- `follow for more`
- `we make clothes like this`
- copy-pasting the same comment on five posts.

### DM Strategy

Send only when there is a reason. Keep it short. Attach or link one artifact.

Repost pitch:

```text
found your archive posts through the old handheld scans.
we make fictional recovered Action Replay artifacts and built one that fits your page:
[asset]
no pressure. if you repost, please leave the weird crop and filename visible.
```

Design page pitch:

```text
this might be too broken for the main feed, which is why it might fit yours.
fictional magazine scan / fake issue 00 / chrome print ad for an Action Replay drop.
happy to send the clean scan too, but the damaged one feels more correct.
```

Collector page pitch:

```text
we sold the first 20-piece run and archived the packaging mistake instead of hiding it.
thought you might like the inventory sticker / hangtag side of it.
```

Avoid:

- implying a paid placement if none exists,
- asking for a guaranteed repost,
- sending multiple follow-ups,
- attaching huge files,
- asking them to say it is real history.

## Rare Drop Psychology

### How To Talk About The First 20-Piece Sellout

Use:

- `the first 20 left before the page felt finished`
- `we packed twenty, found one mistake, kept the record`
- `first run closed. not deleting the bad files`
- `if you missed it, the archive still has the proof`

Avoid:

- `sold out instantly because we're huge`
- `you slept`
- `next drop will be bigger and better`
- fake urgency or shame.

### Second Release Frame

Do not call it a restock if it is materially different. Use:

- `second restored run`
- `slot b release`
- `same archive, different damage`
- `run 002`
- `public build after first-run error`

Announce like:

```text
SLOT B opens this week.
not a clean restock.
same file family, corrected tag, one error left in.
watch the event flag.
```

### Scarcity Without Annoying People

- State quantities plainly after production is confirmed.
- Do not fake low stock.
- If demand is high, open a waitlist instead of vague urgency.
- Use time windows for unlock access, not pressure language.
- Tell people what will and will not repeat.

### Waitlist Language

- `watch event flag`
- `save contact for unlock window`
- `notify when slot b opens`
- `receive access file`
- `join restore queue`

### Restock Rules

- First run stays archived.
- Reprint must have one visible difference: tag, sticker, color, sleeve mark, packaging insert, or hidden code.
- If exact restock happens, say exact restock. Collector trust matters.
- Preserve one “mistake” as a documented variant only if it happened naturally.

### Collector Value

- Numbered or batched inserts.
- Variant labels: `FIRST RUN`, `RESTORED RUN`, `SLOT B`, `EVENT FLAG`.
- Archive entry for every drop.
- Packaging artifacts saved as part of the object.
- Public postmortem after each drop.
- Hidden code on hangtag unlocking a page.

### Next Quantity Tests

- If first run was 20 and sold out: test 50-75 on the next garment if production risk is manageable.
- Keep 5-10 units as archive/defect/replacement reserve.
- If waitlist exceeds 300 high-intent signups, test 100-150 with a longer window.
- For posters/stickers: 100-250 because lower sizing risk.
- For expensive cut-and-sew: 25-40 until fit data is proven.

### Caption Language

- `first run closed. slot b still empty.`
- `second restored run opens after the hidden page updates.`
- `no clean restock. the next file has a different scar.`
- `if the code works, the page will know.`
- `the archive does not repeat files exactly.`
- `quantity posted when boxes are counted.`

## Hidden Unlock Mechanics

### Website Mechanics

- Cheat code input stores unlocked codes in localStorage.
- Shareable secret pages like `/secret/MEMORYCARD` can unlock a code and send users back to the archive.
- Hidden pixels on event pages reveal codes.
- Password pages can gate product variants without forcing login.
- QR codes on stickers can point to secret pages.
- Alt text or filenames can contain clues.
- Unlock log records non-personal events server-side later.
- Secret variants should be visually distinct and plainly limited.

### Instagram Mechanics

- Hide one code in image edge, not always caption.
- Stories can show a cropped folder path for 24 hours.
- Use polls to pick whether to restore or preserve an error.
- Post a fake forum screenshot that hints at where to click on site.
- Put QR code on packaging preview; let people scan it.
- Use side account `unlock_log_txt` to confirm event windows without giving full hints.
- Random unlock windows should be humane: at least 2-4 hours, with one repeat window for other time zones.

### Code Types

- Discount: `SLOTB10`, single-use later via commerce platform.
- Access: `MEMORYCARD`, unlocks secret page.
- Lore: `DONTCHEAT`, unlocks manifesto/archive file.
- Variant: `SHINY50`, reveals product detail or early access.
- Community: `RUNIT`, prompts a public comment ritual without requiring spam.

### Ethical Guardrail

Never require people to tag multiple friends, spam comments, or DM a keyword for access. Let discovery be the action.

## Controlled Repost Ecosystem

### Roles

- Main account: finished artifacts, product proof, official drop state.
- Recovered archive: damaged files and folder previews.
- Magazine archive: print scans and fake issue history.
- Tester archive: bug reports and production notes.
- Memory card: hidden variants and save-state clues.
- Unlock log: event confirmations and timestamps.
- Forum mirror: community rumor texture.
- External micro-pages: repost strongest standalone artifacts.

### Repost Cadence

- Side account reposts main 6-24 hours later, not immediately.
- Main reposts side accounts at most 2-3 times/week.
- External repost pitch max 3/day.
- During drop week, side accounts can intensify stories but not all post feed on the same hour.

### Repost Caption Styles

- `same file showed up clean on main`
- `main account posted the restored version`
- `this matches file_004`
- `thread mentioned this before the drop page changed`
- `event window confirmed. no code posted here`

### Cross-Comment Behavior

- One side account comment per main post is enough.
- Do not have all side accounts talk to each other in public.
- If two side accounts interact, let it be a correction or contradiction.
- Main account should not act surprised every time.

### Avoid Obvious Self-Promotion

- Do not use identical vocabulary across accounts.
- Do not repost instantly.
- Do not have side accounts praise the product like customers.
- Do not create fake testimonials.
- Keep account design and posting defects distinct.

Dashboard views:

- Daily pulse: follows, unfollows, net, saves, shares, website clicks.
- Content lane performance: saves/share rate by archive/product/unlock/drop.
- Unlock log: code entries, path, source, signups after unlock.
- Drop readiness: waitlist, product clicks, quantity decision, risk notes.
- Community map: reposts, DMs, pages that actually drove saves.

## Product Decision Thresholds

- If save rate is high but website clicks low: post more hidden-code bridge content.
- If shares spike on fake docs: produce a carousel version and pitch archive pages.
- If profile visits spike but follows lag: profile bio/pinned posts are too confusing.
- If unfollows spike after commerce posts: commerce language got too normal or too frequent.
- If unlocks happen but signups do not: reward is unclear or capture copy is wrong.
- If waitlist exceeds planned quantity by 5x: increase production carefully or split into two runs.
